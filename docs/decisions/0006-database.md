# ADR-0006: Database

- **Status:** Accepted
- **Date:** 2026-10-05

## Context

Bursar's safety claims (no tenant sees another's data, an action is never made twice, a ledger always balances, an audit log is never edited) are only as strong as the layer that holds them. Application code has bugs and gets rewritten; a constraint in the database is checked on every write, whoever wrote it. So the database enforces what it can, and application code is the second line, not the first.

## Decision

| Concern | Choice | Why | Rejected |
| --- | --- | --- | --- |
| Engine and access | Postgres, with Drizzle for typed queries over node-postgres. Migrations are generated by drizzle-kit from the schema, plus one hand-written migration for what a schema file cannot say | The plan and PayPal's guidance assume Postgres; Drizzle keeps SQL visible and typed | Prisma (its own engine, a weak story for RLS and triggers); string-built SQL |
| Tenant isolation | Row-level security on every table with an `org_id`, keyed on `app.org_id`. `withOrg` sets it per transaction and drops to a role (`bursar_app`) that RLS applies to. System code uses the connection's own role | A forgotten `WHERE` cannot leak. It works on managed Postgres, which gives no BYPASSRLS role and where the owner role runs migrations | Schema per tenant; `WHERE` clauses alone; `FORCE ROW LEVEL SECURITY`, which would block system jobs; a flag that lets a session bypass the policy |
| Types in the database | Text ids with a CHECK on prefix and ULID shape; enums as text with a CHECK generated from `@bursar/schemas`; money as `bigint` minor units with a currency | The database refuses what the types refuse. A new enum value is a migration, not a type change | Postgres enum types (hard to evolve); `numeric` money |
| Invariants | Unique idempotency key; a trigger over a transition table seeded from `ACTION_TRANSITIONS`, with a test keeping them equal; CHECKs for the entity rules; append-only audit log, ledger and policy versions; a deferred trigger that balances each ledger transaction | Each is stated once, where it cannot be skipped | Leaving them to the code that happens to write the rows |
| Tests | PGlite, real Postgres in WebAssembly, so CI and every laptop run them with no Docker. `docker-compose.yml` gives a development server | Fast, hermetic, nothing to install | A Postgres service in CI only; mocking the database |
| Scope | The core and money-path tables the next tasks need. Plan tasks, studio layouts, payouts, deliveries, reconciliations and agent runs wait for their features | Each lands as a migration with the feature that uses it | Building every table from the plan up front |

## Consequences

- **System code is cross-tenant.** The Verifier, webhook ingest and cron use the pool directly, so they can see every tenant. They are few, they are reviewed as such, and tenant-facing code gets only `withOrg`.
- **RLS protects against mistakes, not against SQL injection.** An attacker who can run SQL can set `app.org_id`. The defence against that is not letting them.
- **`missions.envelope_id` has no foreign key**, because the envelope points back at its mission and a cycle would force deferred inserts. The envelope's own foreign key holds the link.
- **Timestamps are `timestamptz`, except the audit log's `ts`**, which is text: the hash covers its exact spelling and a round trip through `timestamptz` would change it.
- **A migration that has been applied is never edited.** Changes are new migrations.

## Verification (2026-10-05)

- 21 tests on PGlite: tenant isolation (no `WHERE`, no organisation set, cross-tenant insert, update and delete, global tables hidden), a guard that every table with an `org_id` has RLS and every other table is classified, each invariant above refused by the database, and an audit chain stored and read back that `@bursar/audit` still verifies.
- The migrations were applied twice to a real Postgres 14 and `withOrg` was exercised through node-postgres: tenants were isolated, a cross-tenant insert was refused, and `bursar_app` is neither a superuser nor BYPASSRLS. The Docker Compose file was not run.
